## 总结

- 解析零拷贝 0.385 µs ~ 112.6 µs, 为 RapidJSON 的 **0.20× ~ 0.96×**; 自包含为 **0.26× ~ 0.97×**
- **吞吐**: `StringObject_64x32` 约 3.4 GB/s, `ArrayOfObjects_2048` 约 1.05 GB/s (解析) / 1.04 GB/s (序列化)
- **正确性**: 十进制到双精度全量正确舍入 (Clinger / 128 位幂表 / 大整数三档), 极端指数与次正规数无 ULP 偏差

## 可优化方向

| 方向                                                        | 预期收益                                                          | 复杂度 |
|-------------------------------------------------------------|-------------------------------------------------------------------|:------:|
| 成员登记由 32 字节压到 24 字节 (键前缀与值内联共用固定字段) | 对象密集文档的成员数组带宽下降约 25%, `ArrayOfObjects` 再快 5%~8% |   高   |
| 小对象的成员数组内联进容器节点 (≤2 成员时省一次分配)        | `Nested_8x32` 这类多容器小文档提升明显                            |   中   |
| 数字扫描与十进制转换合并为一趟 (省掉解析器的第二遍扫描)     | 长小数/大指数文档的实数解析再快 10%~15%                           |   中   |
| `json_builder` 复用解析期的预留策略                         | 构建路径的分配次数下降                                            |   低   |
| 缩进序列化与成员查找纳入对照表                              | 覆盖剩余公开 API 的性能画像                                       |   低   |
