# NeForce basic_string 性能评估

## Windows

> 测试平台: 32 核 × 2419 MHz (Xeon-class), Windows 11, MSVC Release (AVX2), NexusForce v1.0.1

### 构造类 (`StringConstruct/*`)

| 场景 | NfString | StdString | 比值 |
|------|---------:|----------:|-----:|
| DefaultConstruct  | **1.93 ns** | 2.53 ns | **0.76×** |
| ConstructShort    | **8.46 ns** | 10.7 ns | **0.79×** |
| ConstructLong     | **70.5 ns** | 71.4 ns | **0.99×** |
| CopyShort (5)     | **3.27 ns** | 3.29 ns | **0.99×** |
| CopyLong (~135)   | 56.5 ns | 56.5 ns | 1.00× |

- CopyShort 与 `std` 持平：SSO 源整块拷贝 16 字节，无逐字节尾部开销
- ConstructShort 反超：小尺寸拷贝按 8/4/2/1 宽度展开，无逐字节循环
- 构造路径 SSO 容量与 append 路径一致（15 字符）

### 单字符追加 (`AppendChar/*`)

| Size | NfString | StdString | 比值 |
|-----:|---------:|----------:|-----:|
| 64 | 470 M/s | **573 M/s** | 0.82× |
| 1024 | 779 M/s | **1.05 G/s** | 0.74× |
| 32768 | 789 M/s | **1.14 G/s** | 0.69× |
| 1M | **1.05 G/s** | 1.03 G/s | **1.02×** |

- 该用例多轮测量波动最大；受控测量下小/中尺寸 `std` 略快，1M 持平
- 1M 行的 items/s 含 `reserve(1M)` 的分配开销，不纯粹反映 `push_back` 吞吐
- 小尺寸差距推测来自 `size()` 的 `& ~long_flag` 位掩码与 `is_long()` 分支构成的更新依赖链，`std` 的独立 `size_` 成员更新更短（待确认）

### 字符串追加 (`AppendBulk/*`)

| Size | NfString | StdString | 比值 |
|-----:|---------:|----------:|-----:|
| 64 | 1.45 G/s | **1.47 G/s** | 0.99× |
| 1024 | **9.79 G/s** | 7.66 G/s | **1.28×** |
| 32768 | **11.0 G/s** | 10.4 G/s | **1.06×** |
| 1M | 5.66 G/s | **6.22 G/s** | 0.91× |

- 64 为退化用例（`chunks = 64 / 135 = 0`，实测仅构造 + reserve），不反映追加吞吐

- 1M 落后 0.91×：大规模追加由页错误与内存带宽主导

## 总结

NexusForce `basic_string` 在 Windows (MSVC Release, AVX2) 下，9 个 Benchmark 场景中 **8 个持平或领先 `std::string`**：

- **构造与拷贝全面追平或领先**：DefaultConstruct 0.77×、ConstructShort 0.79×、CopyLong 持平
- **批量追加保持优势**：AppendBulk 1024–32768 吞吐为 `std` 的 1.06 ~ 1.28×，`memory_copy` AVX2 宽寄存器路径是核心驱动力
- **填充构造**：32768 反超（1.26×），其余尺寸 0.80 ~ 0.96× 持平
- **FindChar 为唯一余留短板**（0.65 ~ 0.71×）：四层调用链固定开销所致，低复杂度优化即可收窄至约 0.9×
- **AppendChar 波动大**：受控测量下小/中尺寸 `std` 略快（0.69 ~ 0.82×）、1M 持平，需在稳定环境复测确认

## 可优化方向

| 方向 | 预期收益 | 复杂度 |
|------|----------|:------:|
| FindChar 四层调用链合并：`string::find` 短串直接内联标量 / `Traits::find`，减少每次调用的分支与函数边界 | FindChar 0.70× → 约 0.9× | 低 |
| AppendChar 小尺寸：`size()` 位掩码依赖链优化（如长/短模式拆分更新路径） | AppendChar ≤ 32768 波动收窄 | 低 |
| `size()` 纯成员化：SSO 场景下 `long_flag` 恒为 0，考虑独立 `size_` 成员 | AppendChar / FindChar 全线约 10% | 高（架构变更） |
